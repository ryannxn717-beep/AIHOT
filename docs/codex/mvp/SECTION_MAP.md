# 栏目对应与合并

## 背景和决定

用户要求覆盖参考站板块，并授权判断合并。延续已确认的顶部导航、重点阅读主栏和热点侧栏，不复制原站侧栏布局。先整合现有阅读路径，再接入没有包含在上游中的模型数据和监控服务。

| 参考板块 | 本站对应 | 合并理由和边界 |
|---|---|---|
| 精选、全部、搜索 | 资讯，精选/全部模式及原筛选 | 数据相关，但精选标准与全量公开池不混淆；保留原地址和搜索 |
| 热点榜、事件详情 | 热点 | 热度是讨论活跃程度，不作为资料可信度评分 |
| 公司/技术/类型主题、大事记 | 主题 | 三种分类统一入口；现有主题内容可用，大事记需要独立核验数据 |
| 日报、周报、月报、归档 | 报告中心 | 统一入口，保留各周期及每期稳定地址 |
| 模型榜、重置监控 | 模型工具 | 共享工具入口，但指标和数据来源不同；上游未提供，需要独立实现 |
| 收藏、外观、字体 | 我的 | 属于个人阅读设置 |
| RSS、API、MCP | 订阅与接入 | 同一公开发布层的不同出口 |
| 关于、反馈、更新、法律 | 更多/关于 | 低频信息无需占主导航 |

## 本轮 P0 范围与验收

资讯、热点、主题、报告、订阅为当前主导航；我的进入更多菜单。精选/全部切换在桌面和手机都可见，继承分类、频道和标签，清除搜索排序及分页。保留原首页、全部动态、每日/每周/每月、详情和收藏地址。

新增报告中心通过现有HTTP API读取三类已发布报告，显示近期目录及各类阅读入口；空目录明确尚未发布，不产生假期数。API失败返回真实错误，不把失败当作空数据。模块在modules/reading，复用公开发布层，不改数据库、Worker、预算或任何外发开关。

模型榜与监控尚未完成：需要可核验评测数据、指标口径以及监控对象/状态接口。已向用户询问监控对象；没有依据时不使用参考站排名、假曲线或假状态。历史大事记同样属于后续数据工作。

更简单方案仅改导航文字，缺少集中报告入口。拒绝合并热点与精选：热度和信息价值不是同一指标；拒绝删旧地址和把所有功能塞入首页，避免破坏链接及阅读层次。

## 验证与限制

5项SSR先失败后通过。独立审查发现手机断网返回报告中心无法恢复，新增真实Chromium离线回退用例先红，接入现有pageReuse后转绿；复审APPROVE。最终类型检查/构建通过，后端731项通过，Web新增后总62项通过，整站smoke33项通过；手机390×844无横向溢出，报告中心的周报链接与我的入口人工验证通过。

初次后端运行误继承开发环境关闭采集/调用的标志，导致假服务测试等待；取消该测试进程后，使用仅携带测试库地址及系统运行路径的隔离环境完成全套731项。业务.env保持关闭，测试没有访问真实模型。

上游不含模型榜、监控和历史大事记，本轮未声称已实现。DeepSeek模型API可用于筛选/摘要，不等于榜单评测数据或第三方服务额度状态接口。尚无真实报告发布、生产部署或大规模内容验收。
