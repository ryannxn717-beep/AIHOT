# AI 简报 MVP

## 目标与范围

基于 KKKKhazix/AIHOT 上游引擎，先交付本地可运行的中文 AI 阅读站。用户已提供购买的域名 aihot.lol，开发名称暂定 AI 简报，待用户确定品牌；域名配置留到部署阶段。用户已要求先执行最小 MVP；采用前一轮提出的顶部导航、重点阅读和独立热点侧栏布局。

P0：首页、搜索、分类、文章详情、真实来源链接、无结果状态、手机阅读。保留原项目后台、采集接口和统一发布层，使用少量人工核验资料验证阅读闭环。P1：用户确定信源、筛选口味及模型预算后运行自动采集与处理。P2：在双方相同近 30 天窗口和去重口径下，有效 AI 内容超过参考站。

本轮不启用真实模型、付费采集、飞书推送或生产部署；不编造模型评分、发布时间、热度或内容数量。法律页面沿用模板，仅用于本地开发，上线前由用户确认。

## 验收

- 首页采用水平导航、重点事件和宽窄分栏，手机端单列。
- 首页重点内容来自统一 API，空库时展示有意义的阅读入口，不生成假新闻。
- 分类和搜索返回实际数据；无匹配结果时能返回完整列表。
- 文章详情包含真实原文链接、原始发布日期及摘要。
- Web 只通过 HTTP 读取 API，页面请求不触发模型。
- Node 24 类型检查、数据库测试、Web 构建和测试、整站 smoke 检查通过。
- 桌面和手机截图检查；密钥、数据库和下载的本地运行时不进 Git。

## 技术选择

推荐复用 Node 24、TypeScript、React Router SSR、Fastify、PostgreSQL 17 与 pg-boss，修改站点配置和少量前端页面。更简单的方案仅配置站名与颜色，无法满足原创布局；拒绝重写采集引擎，因其会重复已有去重、预算回执和发布规则。没有新增业务数据库迁移。

失败模式：上游示范源失效、没有可信发布日期、自动摘要误判、归组失败。MVP 用人工核验的公开材料验证阅读，后续自动化沿用上游等待/告警/重试机制。若现有 API 无法支持内容布局，再考虑扩展读取层，不绕过统一发布层。

## UI 依据

- 21st Tabs Line：https://21st.dev/@uiable/components/tabs-line 。可见说明为当前标签使用下划线；采用此导航提示，用实际路由组织阅读入口。
- 21st News Search：https://21st.dev/@user_xn1cklas/components/news-search 。可见实现线索是 topic 与 items（id、title、url、publishedAt）；采用结果列表与来源/时间信息层次，不复制示例数据或代码。
- Magic UI Blog：https://blog-magicui.vercel.app/ 。参考博客内容优先、分类与文章层次的节奏；不引入付费模板源代码。
- 领域适配：中文资讯、长标题、短摘要、来源证据、少量暖色强调；减少卡片包裹，正文保持易读行宽。
